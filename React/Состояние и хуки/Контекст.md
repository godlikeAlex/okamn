Context позволяет передавать значение глубоко по дереву без ручного prop drilling. Типичные примеры — тема, локаль, авторизация или зависимости уровня приложения.

Компонент с `useContext` подписывается на ближайший Provider. Когда значение Provider меняется по `Object.is`, React перерисовывает всех потребителей этого контекста; `React.memo` не блокирует обновление context.

Поэтому один огромный context с часто меняющимся объектом может давать лишние рендеры. Обычно context разделяют по ответственности, стабилизируют значение при необходимости и помещают Provider не выше, чем нужно.

Context не обязан заменять props и не является полноценным state manager: он решает доставку значения, а само состояние всё равно где-то хранится. В React 19 Provider можно записывать как `<ThemeContext value={...}>`, в старых версиях — `<ThemeContext.Provider>`.
