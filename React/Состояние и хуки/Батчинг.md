Батчинг — это когда React собирает несколько обновлений состояния и обрабатывает их одним рендером. Так UI не показывает промежуточные состояния и выполняется меньше лишней работы.

Обновления внутри одного обработчика ставятся в очередь. Если несколько раз вызвать `setCount(count + 1)`, все вызовы используют один снимок `count`. Чтобы последовательно применить изменения, нужны updater-функции: `setCount(value => value + 1)`.

До React 18 батчинг по умолчанию в основном работал внутри React-обработчиков событий. Начиная с React 18 при использовании `createRoot` автоматический batching распространяется также на Promise, таймеры и нативные обработчики.

Если DOM действительно нужно обновить синхронно до следующей строки, существует `flushSync`, но он ухудшает производительность и нужен редко, в основном для интеграции с внешним кодом.
