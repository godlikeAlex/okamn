Hydration требует, чтобы первый клиентский render выдал ту же структуру, что и сервер. Если разметка отличается, возникает hydration mismatch, а React может пересоздать проблемное поддерево на клиенте.

Частые причины — `Date.now()` и `Math.random()` в render, разная локаль, чтение `window` или `localStorage`, изменившиеся данные, невалидная вложенность HTML и условие `typeof window !== "undefined"`, меняющее JSX.

Обычно исправление — передать клиенту тот же snapshot данных либо сначала отрендерить одинаковый UI и обновить browser-only часть после hydration. Для данных, которые принципиально отличаются, лучше изолировать небольшой участок.

`suppressHydrationWarning` подавляет предупреждение только для ограниченного случая и на один уровень. Это escape hatch, а не способ скрыть систематически разную разметку.
