В React я стараюсь тестировать поведение с точки зрения пользователя, а не внутреннюю реализацию компонента. Тест должен находить элемент по роли или доступному имени, выполнять действие и проверять видимый результат.

Для компонентных и интеграционных тестов обычно используют React Testing Library вместе с Vitest или Jest. Запросы вроде `getByRole` одновременно делают тест устойчивее и подталкивают к доступной разметке.

Моки нужны на внешних границах, например для сети, времени или браузерного API. Не стоит мокать каждый дочерний компонент и проверять внутренний state — такой тест ломается при безопасном рефакторинге.

E2E через Playwright или Cypress проверяет критические пользовательские сценарии в настоящем браузере. Основной объём обычно дают интеграционные тесты, а E2E оставляют для самых важных потоков.
