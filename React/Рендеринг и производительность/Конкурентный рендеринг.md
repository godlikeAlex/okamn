Конкурентный рендеринг позволяет React работать над обновлениями с разным приоритетом. Несрочный render можно приостановить или отбросить, чтобы сначала обработать более важное действие, например ввод пользователя.

Это не многопоточность JavaScript: код компонентов по-прежнему выполняется в основном потоке. React просто планирует небольшие части render-работы и может между ними уступать управление браузеру.

Конкурентные возможности используются через API вроде transitions и Suspense. Отдельный термин «Concurrent Mode» сейчас менее точен: приложение не переключается целиком в специальный режим, конкурентное поведение включается там, где используются соответствующие возможности.

Поскольку render может повторяться и отменяться, компоненты обязаны быть чистыми. Commit при этом не прерывается.
