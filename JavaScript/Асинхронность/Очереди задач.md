Task Queue содержит обычные задачи: первоначальный запуск скрипта, callbacks таймеров, события интерфейса и некоторые другие браузерные операции. Event Loop берёт из очереди по одной task.

Microtask Queue используется для обработчиков Promise, продолжения после `await`, `queueMicrotask` и `MutationObserver`. После завершения каждой task браузер **полностью очищает очередь microtasks** и только потом может перейти к рендерингу и следующей task.

Поэтому microtask, добавленная из другой microtask, тоже выполнится в этом же цикле. Если бесконечно создавать новые microtasks, можно задержать рендеринг и обычные задачи — это называется starvation.

Именно поэтому обработчик Promise обычно выполняется раньше `setTimeout(..., 0)`: они попадают в разные очереди с разным порядком обработки.
