В HTTP/1.1 браузер обычно открывает несколько TCP-соединений, потому что запросы в одном соединении могут блокировать друг друга. Есть keep-alive, но параллелизм ограничен.

HTTP/2 использует одно TCP-соединение и мультиплексирует в нём много потоков. Заголовки сжимаются, а запросы могут передаваться параллельно. Но потеря TCP-пакета задерживает всё соединение, потому что TCP должен восстановить общий порядок байтов.

HTTP/3 работает поверх QUIC на базе UDP. Потоки транспорта независимее, поэтому потеря данных одного потока не блокирует остальные. QUIC также объединяет установку транспортного и защищённого соединения, что может уменьшить задержку.

Семантика HTTP — методы, статусы и заголовки — при этом в основном остаётся той же; меняется способ передачи данных.
