REST — архитектурный подход к API, где система описывается через ресурсы, а действия над ними выражаются стандартной семантикой HTTP.

Например, `GET /users/10` получает пользователя, `POST /users` создаёт нового, `PUT /users/10` заменяет, `PATCH /users/10` частично изменяет, а `DELETE /users/10` удаляет.

У REST есть и более общие принципы: клиент и сервер разделены, запросы stateless — каждый содержит достаточно информации для обработки, ответы могут кешироваться, а интерфейс должен быть единообразным.

REST не равен просто JSON поверх HTTP и не требует буквально копировать CRUD. URL обычно называет ресурс существительным, а смысл операции задают метод, статус ответа и представление ресурса.
